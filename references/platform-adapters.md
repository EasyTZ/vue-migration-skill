# 跨智能体能力适配

迁移规则、配置和证据格式共用一套；工具调用由宿主适配。不要假设 Codex、Claude Code、搭载 DeepSeek 的编程工具具有相同命令、权限或子代理能力。Skill 只描述能力需求，不赋予宿主未提供的权限。

## 启动时检查

在控制目录迁移计划中记录实际宿主名称/版本、操作系统、Node 版本、Skill 实际根目录，以及下列能力的可用性和替代方式，不输出密钥或完整环境变量。

| 能力 | 需要确认 | 不可用时 |
|---|---|---|
| 读取/编辑 | 源只读、目标/控制目录可写，补丁或文件工具 | 明确无法执行的部分；不能只输出计划称迁移完成 |
| 终端 | 能运行 Node、包管理器、检查脚本，读取退出码 | 可继续代码分析，运行结果列待验证 |
| 联网查证 | 官方文档、可信 registry 或获准的网络工具 | 登记版本未核验；不能凭记忆声称最新 |
| 浏览器/测试 | 实际浏览器、自动化 runner、测试服务 | 先运行静态/单测，UI 与真实集成列待验收 |
| 子代理 | 创建、传递上下文、查询状态、汇总结果，实际可写目录 | 按同样任务拆分串行执行 |
| 持久化 | 台账/检查点读写、上下文恢复 | 使用获准的工程外控制目录；没有持久化能力则报告限制 |

使用宿主实际暴露的工具及其文档，不编造通用 `spawn_agent`、`Task`、`Bash` 或浏览器调用名称。子代理上下文中显式提供 Skill 根目录、必要引用、项目契约和可写文件范围；不要假定子代理自动继承主代理的全部历史或技能。

## 项目规则与路径

读取宿主生效的全局/项目/目录规则和源、目标项目约定，例如 AGENTS.md、CLAUDE.md 或客户端规则目录；这些名称是候选，不要求为其他平台额外创建文件。冲突遵守当前宿主的指令优先级，迁移规则不得覆盖用户明确约束。

所有 `<skill目录>` 均解析为本次加载的实际目录；引用相对该目录解析。含空格路径按当前 shell 正确引用。Windows PowerShell 显式采用 UTF-8；POSIX 使用其原生路径，不照搬 PowerShell 语法。不要把某台机器的绝对路径写进公共 Skill 或项目配置示例。

## 平台入口

- Codex：按当前客户端的 Skill 发现机制安装整个目录，保留 SKILL.md、references、scripts 与 assets；通过已发现技能入口或显式指定 SKILL.md 使用。参考 [官方 Skills 文档](https://learn.chatgpt.com/docs/build-skills)。子代理是否可用以当前运行环境为准。
- Claude Code：使用其 Skill 目录和调用机制，保留同样的支持文件。参考 [官方 Skills 文档](https://code.claude.com/docs/en/skills)。本 Skill 不依赖 Claude 专属 frontmatter 或扩展字段。
- DeepSeek：先识别具体承载工具/CLI/IDE 插件和版本。模型支持工具调用不等于客户端支持 Skill 发现、终端或多子代理；由该宿主加载目录并执行流程。不在未确认客户端前给出统一安装路径或子代理 API。
- 无自动 Skill 发现的编程工具：用户可显式要求先读取本目录的 SKILL.md，再按需读取引用及运行脚本。此方式需要实际工具能力；普通文本聊天不能冒称已修改本地项目。

## 兼容性证据

分别记录：规范/目录可读取、辅助脚本通过、子代理协作通过、代表项目迁移通过。任何一项不能替代另一项。CI 只验证脚本与文档结构，不证明智能体遵循流程；模型更换、宿主升级和不同项目仍需对应验证。公开状态以 README 的兼容表为准，未运行的平台标待验证，不把官方支持 Skill 当成此仓库实测通过。
