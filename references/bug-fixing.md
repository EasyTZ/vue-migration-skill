# 迁移时排查并修复项目 BUG

## 范围与判定

迁移包含对所迁源码及相关调用链的主动缺陷审查，在目标工程同步修复有证据且正确预期明确的问题。无需为每个此类修复另行征求许可；若用户明确要求严格等价或本次禁止修 BUG，则记录源缺陷并遵守其范围。既有源工程保持只读，后端、数据库、生产数据和范围外项目不因本流程获得修改授权。

区分三类：源工程已有 BUG、迁移引入 BUG、尚未证实的疑点。静态扫描、类型错误、可疑写法只是线索；不能直接当作业务缺陷。优先通过最小复现、现有测试、接口契约、项目文档及完整数据流确认触发条件和正确预期。源工程无法启动时可提取纯逻辑或建立隔离复现，记录验证边界，不冒称现场复现成功。

正确预期由明确需求、可靠接口契约、既有正确测试或可证实的程序不变量支持。空值崩溃、确定的资源泄漏、过期响应覆盖新查询、未清理的订阅、失败后 loading 永不恢复等，证据充分时直接修复。折扣、金额舍入、权限范围、审批流向、时间口径等若存在多种合理解释，先追查文档与调用方，仍不明确则集中提出具体选择，继续其他可做工作；不能猜规则。

## 每批审查重点

- 数据与边界：null/undefined、0/空串/false 混淆、越界、错误类型转换、日期时区、精度及单位、直接修改共享对象。
- 异步与时序：竞态、旧响应覆盖、重复提交、取消后继续更新、异常吞掉、错误分支未恢复状态、卸载后写入；结合缓存页的激活/失活契约检查。
- 生命周期：定时器、监听器、MQ/WebSocket、图表实例和共享资源的所有权、重复创建及释放。
- 表单与交互：必填与自定义校验、重置残留、分页条件不同步、弹窗重开旧数据、失败重试和重复写入。
- 会话与权限：退出后遗留敏感状态、过期会话、动态路由残留、不受信任输入及危险 HTML。前端隐藏入口不是服务端授权，发现后端缺口应明确记录，不能声称仅前端修复已闭环。

按实际代码选检查项；不强制把每个项目套入全部检查。发现一个已证实模式后，搜索其他调用点、同构页面和生成器源，逐项确认并修复同类缺陷，避免只修首个命中。

## 修复闭环

1. 为问题分配稳定编号，在控制目录 `迁移台账.md` 的缺陷表登记来源、源/目标位置、触发步骤、实际结果、正确预期及依据、影响范围和优先级。
2. 能自动化的问题先建立能暴露原缺陷的失败用例，再做最小必要修复。原实现无法在新测试环境运行时，记录隔离复现或源缺陷证据，并验证目标修复；不能伪造“修前失败”。
3. 修复目标代码并更新相关调用方，不借机改变无关行为。补触发条件、边界、正常路径及必要失败路径回归；可通过可复现的浏览器场景验证的交互问题，也应保存步骤与实际结果。
4. 将源实际错误结果和目标正确结果登记到“允许差异”，注明依据为本 Skill 的迁移同步修复范围或用户具体指令；涉及待定业务规则的另附确认依据。对拍使用正确预期，不为了匹配旧 BUG 改回错误结果，也不整页屏蔽差异。
5. 重跑受影响测试及当前批次门禁。只有修复已落地、回归验证通过且证据可追溯，才能标记已修复；否则标记待确认、待修复或待验证。撤销修复时同步还原状态与差异记录。

报告区分“迁移检查通过”和“缺陷闭环”。交付列明已修复、待确认、待修复及待验证项目；未修复的高风险问题说明影响与验收阻塞范围，不把发现 BUG 数量当成质量证明。不承诺全面读取代码即可找出所有 BUG。
