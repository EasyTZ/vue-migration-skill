# 最新稳定依赖与现代化交付

## 建立执行时版本快照

先列源工程全部直接依赖及使用点，结合锁文件、动态加载、插件注册、外部脚本和部署配置确认真实能力，再决定目标依赖内容。为每项记录保留升级、替换或删除，以及新增依赖的具体用途，不使用 Skill 内置的必装包清单。生产库、构建插件、包管理器、语言检查、lint、测试、CSS 预处理器和浏览器测试工具均按实际需要评估；传递依赖由正常解析及锁文件管理，发现漏洞、废弃或多份运行时再追踪引入链，不手工强制全部传递包为 latest。

优先考察原依赖的 Vue 3 支持和现代使用方式；有受维护的同系方案时评估迁移成本与能力覆盖，无合适版本时选择有依据的替代。构建工具、UI、请求、状态与测试方案均由项目用途、生态维护、部署约束及兼容性共同决定，不因模板偏好强制替换全部库。Vue 3 是本 Skill 的迁移目标，其他依赖不存在固定组合；原项目没有某项能力时，不为了模板完整而新增。

对 npm 包可查询 `npm view <包名> dist-tags --json`，再查询 `npm view <包名>@<候选版本> version engines peerDependencies deprecated --json`；使用项目配置的可信 registry，并记录来源。latest 标签只是候选，须核对官方发布说明、维护分支与迁移指南；不把 beta/rc/next/canary 自动视为稳定版本。框架主版本还应符合用户指定的 Vue 3 范围。

每项在控制目录的版本矩阵记录：源依赖及使用点、目标依赖、源版本、最新稳定候选、选定版本、查询日期/registry、官方依据、engines/peer 要求、升级/替换/删除/新增决定、破坏性变更及验证场景。私有包按内部发布来源核验；无法查询时如实标为未核验，不假称“已最新”。`project.json.targetManifest` 保存实际目标清单；`dependencyPolicy` 记录核验状态及偏离项。workspace、本地路径和受管理的私有依赖保留其合法声明方式，记录解析依据，不伪造成注册表版本。

优先通过改写项目代码、升级宿主 Node/CI、更新配置或替换失维护库，使最新稳定依赖可共同安装。若稳定生态尚无兼容组合，先完成与冲突无关的工作，向用户给出具体冲突与选择。只有用户接受后才能采用较旧受维护版本，并记录理由、影响、复查条件；没有该接受依据不能把这一项标为达标。不要擅自改用预发布或 git 分支包绕过问题。

## 可复现与刷新

- 首次解析后保留一个匹配包管理器的锁文件，记录包管理器精确版本及 Node 支持范围；可用时写入 `packageManager` 和 `engines`，CI 使用一致环境。选 Node 时同时核对当前受支持版本与全部工具链要求。
- 在干净环境以 `npm ci`、`pnpm install --frozen-lockfile` 或对应不可变安装方式复验。正常安装必须无未解决 peer/engine 冲突；包警告逐项归因，不以静默参数隐藏。
- 开工生成快照；短批次复用该快照，长任务在批次边界及交付前重新查询。新稳定版出现时记录差异与升级验证成本，不在正在验证的批次中自动刷新。若交付版本已非最新，报告实际核验日期、差距和处理决定，不用“最新”概括过期快照。
- 不在 manifest 留 `*`、`latest` 或无依据的浮动版本来冒充最新；也不把精确版本固定当成永不升级政策。移除不用的依赖、旧 loader、桥接插件、旧类型包及重复锁文件。

## 按新框架改写

现代化审查面向迁移拥有的源码，不对第三方包或生成文件机械改造：

| 旧实现 | 目标方向与证据 |
|---|---|
| Options/class/decorator、mixin | `<script setup>`、组合式 API、有明确参数与返回值的 composable；按语言方案采用 JS 或 TS，验证初始化顺序和副作用 |
| 全局 Vue 原型、隐式 this、事件总线 | typed 模块服务、provide/inject 或范围明确的事件机制；验证订阅释放与隔离 |
| 旧状态、路由 API、UI 属性 | 所选状态/路由/UI 方案的公开 API；按原项目用途选择依赖，更新调用方与测试，不依赖全局 monkey patch |
| 旧构建专用加载器、CommonJS 浏览器路径 | 所选现代构建工具支持的 ESM、资源导入与公开插件；验证生产路径、拆包及项目形态 |
| 停更组件、内部私有 API、旧库兼容开关 | 维护中的库、公开 API 或范围清晰的项目组件；验证业务行为及可接受视觉差异 |

不为“看起来新”引入不必要抽象，也不因 API 可用就强制使用每个新宏。外部合同允许保留旧字段名和协议，应用内部使用清晰类型与边界转换。业务契约、部署契约和权限不因依赖升级擅自变化；新版 UI 的合理样式差异事先列明并验收，不用旧 DOM/CSS 私有实现强求逐像素复刻。

交付扫描源码、manifest、锁文件和构建配置，对照本项目依赖映射核对不支持目标栈的旧依赖、迁移临时桥接、废弃 API、大范围类型逃逸、全局模拟旧 API 的残留。不要仅凭库名或主版本较小就判定应删除；检查维护状态、目标兼容性与实际用法。扫描命中需阅读上下文；按“已移除 / 外部协议保留 / 经接受的版本例外 / 未完成”逐项结案，不凭文本命中数宣称完成。

## 批量项目复用

先选具有代表性的项目或纵向链路，贯通其实际具备的关键能力、构建与部署验证，再扩大批次；应用可覆盖登录、权限、查询与提交，组件库则覆盖导出、打包及真实消费方。复用改写规则与检查工具，不复制项目的凭证、业务规则或过期版本快照。

自动改写使用 AST/SFC 工具处理结构，先预览 diff；正则只用于明确局部且经复核的规则。批量工具必须可重跑且不重复注入，能报告未识别语法和逐文件失败，不覆盖人工修改。重跑前比较输入快照及已迁文件状态，源工程在迁移期间有新变更时单独建立增量批次，避免悄悄丢失业务修复。

每批维护源文件/入口到目标的覆盖关系及明确删除理由。复用率、文件数和构建成功不能替代业务完成度。最终保留可重复执行的项目测试；迁移工具与证据继续留控制目录。

官方入口（执行时另查实际所选依赖的迁移文档）：[Vue 组合式 API](https://vuejs.org/guide/extras/composition-api-faq)、[Vue script setup](https://vuejs.org/api/sfc-script-setup.html)、[npm view](https://docs.npmjs.com/cli/commands/npm-view)。
