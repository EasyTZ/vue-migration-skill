# 准入、项目配置与范围

首先解决会推翻技术路线的条件，避免先迁页面再发现现场无法运行。

| 项目 | 必须确认的证据与决策 |
|---|---|
| 浏览器 | 现场版本/内核、WebView、WebGL、下载/打印/控件；Vue 3 不支持 IE，不满足时先确认可升级浏览器或替代方案，不能继续承诺现场可运行 |
| 运行环境 | Node、包管理器、锁文件、CI/操作系统、代理及私有包；对照选定工具链 engines 与插件 peer 范围 |
| 源架构 | Vue 精确版本、Router/Vuex、class/decorator、mixin、插件、事件总线、filters、动态组件、render/JSX、运行时模板、SSR/微前端 |
| 接口 | baseURL、代理、鉴权、Cookie/CSRF、拦截器、字段大小写、日期/金额单位、取消/重试/去重、错误与退出语义 |
| 路由和状态 | hash/history、部署 base、权限继承、query/params、动态路由、刷新、页签与缓存、存储键及有效期 |
| 静态资源 | public 路径、require.context、动态 require、webpack loader、字体图标、CSS 深度选择器、CSP、跨域 |
| 外部能力 | MQ/WebSocket、地图、Canvas、图表、Excel/PDF、打印插件、原生桥、Worker/Service Worker |
| 业务风险 | 结算、金额、授权、审批、数据导入/导出、重复写入；测试环境及可逆测试数据 |
| 基线 | 源工程启动命令、可用账号、关键场景和截图；源无法启动时记录原因及证据降级范围 |
| 工程边界 | 控制目录实际路径、源工程是否可写、新工程是否已存在过程资料、源工程 lint/tsc/打包是否会扫描控制目录 |

检查 manifest、源码与部署配置，不收集或输出真实凭证。按 [dependency-policy.md](dependency-policy.md) 为所有直接依赖核验最新稳定版本；不把某次项目的最新版本写成永远正确的版本。版本确定后写精确版本与锁文件，记录核验日期、来源、Node 需求和浏览器要求。旧 CI/Node/浏览器无法支持目标栈时先列出环境升级路线，不默认回退框架版本。

对 monorepo 逐个确认 workspace、共享包与锁文件边界；普查入口应包含路由外页面、动态注册、权限生成菜单、嵌入页、弹窗调用、插件注册、Worker 和定时任务。每个入口都应有目标对应或明确的删除依据，避免“路由可跑但隐蔽功能漏迁”。共享包升级需评估所有消费方，不修改本次范围外项目来强行通过。

## 迁移资料落位

控制目录默认 `<源工程>/migration/`，由 `init-control.mjs` 建立；用户指定其它位置或源工程不可写时，以实际路径为准写入 `project.json` 的 `control.root`。只读只针对老工程既有文件：控制目录是唯一允许新增的目录，任何既有源码、配置、构建产物和锁文件都不得改动。

- 新工程只放项目代码与依赖。一旦发现台账、规范、计划、清单、证据、报告或迁移工具出现在新工程，先移入控制目录再删除，并记入台账。
- 控制目录可能被老工程工具链扫描。先读 tsconfig include、eslint ignore、构建入口和测试 glob；会被纳入时，向用户提出并只在授权后最小化调整忽略配置，登记为“允许差异”。
- 是否把控制目录提交到老工程版本库按项目约定，初始化时就确认。证据、截图和日志默认不提交；台账、规范、计划和验收报告通常需要提交，便于评审。
- 迁移专用工具与一次性脚本放控制目录 `tools/`，输出只落控制目录或工程外；不为了就近而放进新工程。

项目配置采用 `assets/project.example.json`，存放于控制目录根；`control` 下的路径按控制目录相对路径解析。`targetManifest` 根据实际依赖决策填写目标包清单与命令，`dependencyDecisions` 记录源依赖、用途/使用点、目标依赖或删除决定及依据；空对象不代表普查完成。旧配置中的固定 `versions` 表需转换，不直接套用。可安装外部依赖填写核验后的稳定精确版本；库的 peer 范围、工作区协议及特殊来源保留真实契约并单列依据。源/目标路径必须不同，目标不得位于源工程内部，控制目录不得位于目标工程内部。

台账每个页面至少记录：源路径、目标路径、所属路由/入口、依赖、风险、批次、状态、证据链接、待决策事项。建议状态为未开始、进行中、代码已迁、自动验证通过、对拍通过、验收通过、阻塞。生成清单和人工验收数据分开保存；再次普查按路径合并，不能清空历史状态。台账中的证据链接写控制目录内的相对路径，不复用指向新工程的临时路径。

源缺陷与迁移引入缺陷分开：迁移缺陷修复到正确基线；源缺陷按 [bug-fixing.md](bug-fixing.md) 在目标工程同步修复，登记预期依据、差异与回归证据。正确行为不明确时标记待确认。不能用“等价”保留已证实 BUG，也不能把个人偏好当成缺陷；缺陷修复不授权改动源工程或范围外系统。
