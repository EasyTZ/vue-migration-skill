# 整体工程架构迁移

按实际工程形态检查运行时、构建、语言、路由、状态、UI、请求、测试和部署，不能把只改 Vue 组件版本当成整仓架构迁移完成。这里的库名是候选方案，不要求所有工程采用同一套依赖，也不预填版本号。

## 架构决策与覆盖

普查源 manifest 和锁文件之外，还须读取入口、构建脚本、配置、CI、容器/反向代理及宿主接入。为每个实际能力在迁移规范登记：源实现、实际使用点、目标方案、迁移文件、前置依赖和验收场景。

至少核对：

- Vue 编译/运行时、JS/TS、组件写法和插件注册；SSR 与多实例环境的状态隔离。
- 构建工具、loader/plugin、HTML/多页入口、alias、公开环境变量、运行时配置、代理、资源与模块解析。
- 路由权限、状态及持久化、UI/图标/主题、请求层、外部 SDK 与 Worker。
- lint、语言检查、单元/组件/E2E 测试、包管理器与锁文件、CI、生产产物及部署入口。

原项目未使用的能力标为不适用并说明，不为了架构图新增依赖。改变构建、测试与部署配置是迁移范围内的实现工作，但实际部署、生产配置变更或范围外仓库修改仍遵守用户授权。

## Vue CLI / webpack → Vite 候选路线

普通应用可评估 Vite；存在特殊 webpack 能力、SSR 框架、微前端宿主或库发布协议时，先核对现代替代及宿主支持，不直接套 SPA 模板。

选定 Vite 后逐项核对：

| 能力 | 实现与验证 |
|---|---|
| 入口/模块 | HTML、多页入口、main、ESM、alias、动态模块；迁移 require.context 等并验证导入覆盖 |
| 环境/代理 | 区分 mode、DEV/PROD 和源 NODE_ENV 业务语义；迁移公开变量与代理，保留运行时配置来源 |
| 插件/loader | 每项映射到内置能力、受维护插件或代码重写，确认插件顺序与生产模式；禁止只删除报错配置 |
| 资源/样式 | public 与源码资源、动态 URL、SVG/字体、预处理器、CSS 全局注入、按需导入、主题覆盖顺序 |
| 平台边界 | 不把 Node 内置模块自动视为浏览器能力；检查 SSR、Worker、原生桥或微前端外部化需求 |
| 构建参数 | 按当前所选版本核对 target、base、outDir、source map、拆包与插件选项；不固化旧底层打包器参数 |
| 交付链路 | 同步 scripts、CI 安装/检查/构建、产物上传和服务端静态路径；不擅自执行生产发布 |

开发服务通过后还需生产产物验证：直达刷新、子路径、缓存/页签、chunk、公开资源、接口/Cookie/跨域与配置注入。记录可测量的性能基线和结果，不能凭换用 Vite 就承诺固定提速倍数。

## 配套层改写与验收

- 路由：选择兼容 Vue 3 的现代方案，保留已有导航与权限契约；无路由项目不新增。
- 状态：如选 Pinia，逐项映射 Vuex action/getter/订阅及持久化语义；全局服务、事件与局部页面状态分清生命周期。
- UI：按实际库及目标版本改属性、插槽、校验、弹窗、样式和图标；不要让新旧完整 UI 运行时及兼容层永久并存。
- 请求：保持后端协议、日期/金额单位及鉴权语义，统一基础能力，补取消、异常、过期响应与退出回归。
- 语言：按用户及项目选 JS/TS，检查目标源码和配置；类型声明不代替真实 API，不能靠关闭检查过关。
- 质量：迁移旧 runner 的配置、mock、测试环境与断言；选型可以变化，原有效场景不得随工具更换而消失。
- CI/部署：在一致运行时执行不可变安装及检查，验证产物路径和运行方式；本 Skill 仓库自身的 CI 不代表目标工程 CI 已完成。

## 分批顺序

通常先贯通构建/环境与公共契约，再迁代表链路，验证通过后开放独立业务批次。构建、依赖清单和共享配置由指定负责人管理；工程形态和依赖方向不同可以调整顺序，但不能在基础契约未稳定时并行创建竞争实现。

交付同时给出源码覆盖与架构层覆盖。所有适用层完成改写、可复现安装、项目检查、生产产物及业务链路验证后，才能把整仓架构迁移列为完成；未满足项登记到台账。

官方入口：[Vue 工具链](https://vuejs.org/guide/scaling-up/tooling)、[框架级迁移建议](https://v3-migration.vuejs.org/recommendations.html)、[Vite 功能](https://vite.dev/guide/features)、[Vite 迁移指南](https://vite.dev/guide/migration)。执行时再核对具体依赖所选版本的文档。
