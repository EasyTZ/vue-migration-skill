# 多子代理并行迁移

本 Skill 允许在工具和环境支持时主动调用多个子代理，以加速依赖调查、模块迁移、BUG 排查和验证。并发数按可用额度、任务独立性和资源预算决定，不写死代理数量；不支持时按相同批次单代理执行，不把缺少并行工具当成阻塞。子代理是当前任务的协作单元，不创建用户侧新聊天来代替子任务。

## 先建立可共享的契约

主代理先确认源/目标/控制目录、业务边界、依赖映射和代表链路。可并行调查互不依赖的领域，但框架和共享依赖的最终选择由主代理统一收敛。先完成并验证公共接口、状态/权限/路由约定，再按依赖图分派独立模块；强依赖或同文件修改串行处理。

每个任务明确：源文件和调用链、目标文件写入范围、共享契约版本、禁止修改文件、允许的 BUG 修复范围、测试场景、证据目录、交付条件。子代理遇到缺失共享接口时报告具体需求，不自行创建竞争实现或修改冻结的契约。

## 文件与运行资源所有权

- 同一时刻一个文件只有一个写入者。主代理管理 manifest、锁文件、根配置、路由汇总、公共 API、全局样式、项目配置及总台账；子代理提供变更需求，由主代理统一集成。确需下放共享文件时先明确移交所有权。
- 证据放控制目录独立子目录；结果由主代理合入台账，避免代理同时改一张表。页面相关项目测试由该页面负责人维护，共享测试由指定负责人维护。
- 优先复用当前工作区，分配互不重叠的文件；需要隔离且环境允许时使用独立工作树，统一基点并审查合并差异。不要复制完整 node_modules 给每个代理。
- 安装、锁文件写入、全量构建、共享测试服务由主代理协调串行执行；模块级测试在资源允许时并行。分配独立端口、测试账号或数据命名空间，不争用浏览器状态和可变夹具；不得停止其他人的服务。

## 动态调度与集成验收

子代理回报实际修改文件、完成范围、依赖需求、BUG 编号和修复依据、测试命令/退出码、证据位置与未完成项。主代理持续收取结果，按依赖解锁后续任务；一个任务阻塞时继续独立工作，不重复派发同一写入范围。更换负责人前确认旧任务已停止写入，并保存当前变更和检查点。

先集成代表链路及公共组件，再开放依赖其上的并行批次。批内独立模块可以并行，不能越过前置验收盲目扩大业务范围。共享契约变动须通知所有受影响代理并重验消费方。

子代理的“完成”只是模块交付，不等于整体通过。主代理审查 diff 和实际证据、解决冲突与遗漏，集成后统一执行项目适用门禁、入口覆盖、依赖检查、SFC 巡检、边界检查和跨模块业务回归；不得把并发写入时的暂时构建结果当最终结论。检查点增加任务负责人、文件所有权、已集成/待集成结果及运行资源，方便中断续作。
