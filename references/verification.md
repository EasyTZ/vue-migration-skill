# 验证与交付证据

## 四道门禁与编译覆盖

按项目选型落实 lint、静态检查、test、build，实际执行适用命令并记录退出码与时间。TypeScript 工程必须执行类型检查；JavaScript 工程使用适合项目的静态检查，不为凑齐命令强制引入 TypeScript。不适用项记录技术依据，不能把因配置缺失或执行失败的检查标成不适用。测试不得为零；已有失败记录基线，但最终不能将未解决失败写成全绿。路由未引用的页面可能不进入所选工具的构建；类型检查也不能代替模板与样式编译。

目标存在 Vue SFC 时，确保可从目标工程解析与运行时匹配的官方 SFC 编译器后运行（特殊编译配置需配套验证，不能为此强制换构建工具）：

```sh
node <skill目录>/scripts/check-sfc.mjs <目标工程>
```

该工具遍历 src 下所有 .vue，使用目标工程自己的编译器检查 SFC/script/template/style，不做打包、类型检查或实际挂载。外部 src 块会明确报待处理，不能略过宣称全量成功。它不是语义验收工具；编译成功仍需下列验证。它同时按 `<transition name>` 反查 Vue 2 遗留的过渡类名（`.x-enter` / `.x-leave`，含 `<Transition>` 与无 name 时的默认 `v-` 前缀）并报告 `<transition>` 里直接嵌 `<router-view>`：这两类都能编译通过，却会让每次切页白等一段过渡时长或让过渡彻底失效，确证的按失败处理，形似但没有对应 `<transition>`（同名或默认 `v-` 前缀）引用的只作候选、需人工确认。

门禁和编译通过都不等于页面能渲染：模板 ref 与数据同名、组件 API 用错、插槽和属性透传不符等只在挂载时报错，lint、类型检查和构建都察觉不到。挂载冒烟与入口走查见“行为证据”，并计入完成标准。

## 运行验收门禁（必做）

代码门禁、SFC 编译和单元测试都不证明目标工程能在本机跑起来。代码迁移完成后，必须按[自动化运行验收](auto-acceptance.md)托管启动目标工程，执行 HTTP 巡检、浏览器渲染/控制台/请求检查、交互场景、接口覆盖与新旧基线对比，并用 `acceptance.mjs` 生成复原度报告；从老工程抽取功能面的方法见[能力抽取](capability-extraction.md)。

- 默认门禁为总分 ≥ 99%（`acceptance.minScore`）且阻塞项为空；阻塞项、降级与允许差异的口径以运行验收文档为准。
- 服务必须由 `serve-target.mjs` 或验收编排器托管启停，状态/日志/端口证据落控制目录；交付前停止并确认端口释放。
- 缺少浏览器、后端或账号时，只报告实际完成的范围；视觉/交互/接口维度未验收不能宣称 99%。
- 复原度分数由机器证据合成，不能替代业务人工验收；截图、Canvas/图表仍要人工复核。

## 工程边界检查

老工程装过程资料、新工程装项目代码，这条边界要实际核对而不是凭印象。交付前运行并记录退出码：

```sh
node <skill目录>/scripts/check-boundary.mjs <控制目录> <目标工程>
```

它按 `project.json` 解析路径，报告新工程内的台账、计划、规范、清单、证据、报告、`migration/` 目录和迁移配置或普查快照的副本。命中必须阅读内容、确认归属；已证实的过程资料移入控制目录再从新工程删除，并在台账登记。业务文件的误报应修正规则并补回归，不能自动移动。仅含相似 JSON 字段的提醒需要人工确认，不视为已证实越界。

## 行为证据

验证从已提交的 manifest 与锁文件在干净环境安装开始，记录 Node、包管理器和浏览器版本。检查依赖策略中的最新版本核验与例外记录；对目标源码执行现代化残留审查，不能仅以 Vue 3 能运行作为现代化通过。CI 同时运行项目检查，不能只验证本地带缓存的 node_modules。

- 迁移后首次可达的页面（新补的路由、从注释恢复的入口、菜单里新出现的页面）逐个做挂载冒烟：用目标版本的测试工具挂载页面，断言关键列表有行、关键弹窗能打开并回填，控制台没有渲染错误、`Invalid prop` 警告或未捕获异常。正常数据必做；空数据与接口失败至少覆盖列表类页面，确认是空表而不是白屏。冒烟用例本身是项目测试，留在目标工程；页面挂载通常需要 router、状态与 UI 库的测试工厂，抽一份公用 helper，不要每个页面抄一遍。
- 手动渲染的保留页/页签额外核三项：切页后旧页的日期面板、下拉、tooltip 不残留；业务页面根节点的绝对定位与 100% 宽高仍生效（多根组件最易丢）；窄列里的日期框与行内 select 有正常宽度，不是只剩图标。
- 组件库样式/几何回归：按[组件库样式与几何迁移](ui-style-migration.md)的清单核对控件高度与宽度（small 与 default 两档）、行内表单间距、表格行高与单元格留白、带自定义头/体/脚底色的弹窗、抽屉、上传区和裸 `el-col` 栅格；用计算样式探针检查构建 CSS 的级联，再逐页现场验收。字体档位、字体图标改 SVG 等允许差异单独登记，不能用于解释布局回归。
- 用真实关键 UI 库挂载关键组件；按需要在请求 adapter 拦截以验证真实拦截器后的 URL、method、headers、params/body、字段类型、日期及单位。adapter config 不是完整线上报文；multipart、Cookie、浏览器编码、代理路径等用浏览器网络或测试服务验证。
- 校验自检：留空必填字段必须显示错误且不发请求，填入有效值才发一次请求。若异步校验异常，先复现并检查 test runner 依赖处理与具体版本；仅在证实需要时配置 inline，不能硬套某个 Vitest 配置版本，也不能一律把问题归咎于测试。
- 覆盖打开/关闭/重开弹窗、查询/重置/分页、权限拒绝、失败重试、取消、返回刷新、缓存与页签 active 切换。
- 切页体感单独走一遍：连续点几个菜单，确认不是"先僵住再瞬间切换"。每次切换都固定停顿、又看不到淡入淡出，基本就是过渡首尾类名没跟着 Vue 3 改名（时长被读走、属性不变），或 `mode="out-in"` 叠了一段看不见的动画；用 Performance 面板录一次切换，把停顿长度和 `<transition>` 声明的时长对上再改，不要凭感觉调。
- 按台账的路由对照表逐个入口走查：每个菜单项、每个页面按钮、每条返回路径都要落在预期页面而不是兜底页，落地页有实际内容而不是空白。按钮没反应、跳回首页、表格空着不报错，都按接线缺陷登记，不能算“能跳就行”。
- 金额与关键业务差分：相同输入给新旧实现，比较输出及请求。覆盖 0、负值、边界、空值、精度、舍入、元/分、累加与溢出；保留源公式及行号供人工复核。
- 定时器/MQ/事件按源契约核对创建、暂停、卸载与重进，不擅自“优化”可观察时序；确认迁移未新增泄漏。
- 真实生产构建预览验证子路径部署、直达刷新、懒加载 chunk、资源 URL、跨域/代理、CSP 与环境变量；开发服务可用不代表部署可用。涉及 SSR/微前端/原生桥时验证对应宿主边界。
- 按项目规模比较启动与主要页面耗时、构建产物体积、重复访问内存/订阅增长；预算根据源基线和实际需求设定，不写通用固定阈值。检查键盘操作、焦点归还、弹窗与表单可访问性，避免新版 UI 替换造成可观察退化。

截图、日志、网络抓包和对拍结果一律写控制目录 `evidence/`，不落到新工程。对拍脚本、固定夹具和浏览器驱动配置放控制目录 `tools/`；需要在新工程运行的断言应当是项目自身测试的一部分。

## 新旧对拍

给新旧应用固定相同数据、账号权限、视口、时区/语言、字体和浏览器版本，等待相同的业务就绪信号。选择登录、导航、每类公共组件、各页核心交互与高风险链路，保存场景清单及结果。

对照用户可观察的内容、布局、关键 DOM/可访问性语义及请求序列；UI 库内部 DOM 不要求逐字相同。只对预先记录的时钟、随机值、动画等进行掩码或容差处理，禁止用大范围忽略隐藏差异。Canvas/图表必须截图检查；必要时人工复核。

源 BUG 的修复按 [bug-fixing.md](bug-fixing.md) 单列预期：保存源错误行为证据及目标正确行为断言，未受影响的行为继续对拍。金额、权限及关键流程的修复必须有明确正确预期，必要人工复核仍保留。已登记的 BUG 修复差异不要求重现旧错误，也不能以“修 BUG”为由忽略无关回归。

禁止在生产环境自动执行结算、删改或真实付款。写操作使用已授权的测试环境及可回收数据；无可用后端时可用固定响应重放验证，但把真实集成列为未验收，不能以 mock 通过代替后端验收。

## 状态与报告

每场景记录：源/目标提交或快照、运行配置（脱敏）、步骤、预期、实际、证据位置、结果、允许差异及批准依据。证据位置写在控制目录 `evidence/` 下的相对路径。截图/日志不默认提交仓库；验收报告与台账同类，放控制目录并随老工程交付。

完成标准：全部入口与权限结构核对、入口与路由对照表逐项走查、占位为零、最新稳定依赖核验及例外结案、现代化残留审查通过、四道门禁绿、SFC 全量通过、首次可达页面挂载冒烟通过、边界检查通过、关键行为通过、新旧对拍通过、生产构建部署验证通过、**托管启动成功且复原度门禁通过（或缺口逐项登记）**、服务已停止且端口释放、必要人工复核完成、干净安装/启动/构建可复现。未满足时准确列状态与待办，不能仅凭测试数量、组件计数或分数称完成。

文件名正则与 token 比对仅提供候选差异；改写会自然改变 AST/token，不能用逐字相同代替功能证据。遇到编译巡检和 regex 的假阳性，修工具的识别范围并保留真实断言。
