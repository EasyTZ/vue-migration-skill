# 目标工程模板契约

附带 `init-target.mjs` 是清单初始化器，不是固定技术栈的脚手架。先分析源工程的 manifest、锁文件、实际使用点、部署方式及对外接口，完成依赖映射，再填控制目录中的 `project.json.targetManifest` 和包管理器。现有目标工程逐项补齐，不覆盖重建。

`targetManifest` 存放本项目实际选定的包清单，包括名称、模块类型、脚本、生产/开发依赖，以及项目形态需要的导出、workspace 或其他字段；依赖版本在执行时核验，不在 Skill 中预填。初始化器仅生成 `package.json`、README、`.gitignore`，不安装，也不生成某个构建工具、路由、状态或 UI 库的入口。随后按所选技术路线的官方模板补齐源代码与配置。它只检查输入和工程边界，不证明版本最新、依赖兼容或工程可运行。

旧控制配置续作时，把旧 `versions` 的有效决策迁入实际目标清单并重新核验，不照抄固定包列表。若使用附带的 SFC 巡检器，需确保目标工程能直接解析与 Vue 编译链匹配的编译器，不依赖偶然的传递包提升。

## 新工程只装项目内容

目标工程要能独立安装、运行、构建、测试。目录按项目形态与现有约定组织，下列内容仅在实际需要时建立：

```text
src/api/          请求与领域 API（有接口调用时）
src/components/   可复用组件
src/composables/  生命周期与组合式能力
src/stores/       需要共享的状态（有状态库时）
src/router/       路由及权限接入（有路由时）
src/views/        尽量保留源页面相对路径
src/utils/        无业务副作用的工具与反馈封装
tests/            单测、组件测试、契约与回归场景
适用的应用/SSR/组件库/宿主入口
package.json      锁文件              README          .env.example
所选构建、语言检查、lint 与测试配置
```

不属于目标工程：迁移台账、迁移规范、迁移计划书、普查清单、对拍截图与日志、验收报告、迁移专用脚本、`migration/` 目录。这些留在老工程的控制目录，见 SKILL.md 的“工程边界”。README 只写本项目如何安装、启动、构建、测试和配置公开变量，不承担台账职责；生成后运行 `check-boundary.mjs` 复核。

## 骨架接入规则

- 环境变量只暴露公开配置，前端变量不是秘密存储。保留源运行时配置与 hostname 注入方式，除非用户同意改变部署契约。
- 按源项目实际需求选择请求实现，集中鉴权、字段大小写、baseURL 和错误处理，不预设特定库、大写键或 storage 名。
- 原项目使用共享状态时，按目标状态方案核对读取、更新、异步返回值、订阅、持久化与退出清理；保持响应性。没有共享状态需求时不强制安装状态库。
- 有路由时保留 hash/history 和 base；人工外壳、active prop、keep-alive、手动渲染路由组件都属于现存契约，不能一律改成默认路由外壳。无路由的项目不为套模板新增路由。
- 语言方案按项目约定选择；采用 TS 时以可维护类型为目标，边界数据使用明确的 unknown + 校验，不用全仓 any 获得绿灯；保留 JS 时配置适用的静态检查，不将缺少 TS 包视为迁移失败。
- lint 与测试工具版本也需要核验。将适用的 lint、语言/类型检查、test、build 接入 package.json 与 CI，JS 不强制引入 TS 检查工具，不适用项记录理由；测试 0 项不能算 test 通过。
- 所有直接依赖按 [dependency-policy.md](dependency-policy.md) 核验最新稳定版本，包括周边库与开发工具。已有目标工程也适用。优先自带类型，再用匹配的 @types；缺失时允许范围有限、可解释的声明，不用声明伪造运行时并不存在的 API。
- 按所选版本的官方模板核对构建插件、语言及检查配置；覆盖配置文件与源文件的适用检查。不要通过跳过库类型检查、排除业务文件或关闭规则来掩盖迁移错误。

补齐源码配置后安装锁定依赖，执行适用的静态检查与 build，并验证实际入口；随后接入公共能力，建立 lint、所选测试运行器及行为对拍，再迁移业务批次。组件库验证真实消费方，SSR 验证服务端渲染和 hydration，微前端验证宿主集成。对拍脚本与浏览器驱动配置放老工程控制目录 `tools/`，只在目标工程保留项目自身测试；初始化成功不代表迁移完成。
